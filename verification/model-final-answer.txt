## 需求落点

- **分组身份**：按 `(IPv6 源, 目的, 32 位 id)` 三元组分组，绝不仅看 id——两个来源同 id 会各自独立完成。
- **头链一致性**：组内 Fragment Header 的 `nh` 与整条不可分片扩展头链的线上字节必须一致，冲突整组 `HEADER_CONFLICT`。
- **线上长度对齐**：片段正文直接从 `IPv6.original` 按 `plen` 切片（`_strict6_wire_geometry`），截断残片、虚高 plen → `BAD_PLEN`；链路层 padding 因落在 `plen` 之外永不入数据。
- **RFC 5722**：任意区间重叠（含完全相同的重复片）整组丢弃，重复但字节不同 → `OVERLAP`，完全相同 → `DUPLICATE`；非末片长度必须是 8 的倍数；必须有 offset=0 首片、唯一 M=0 末片、区间连续，分别对应 `NON_LAST_NOT_MULT8 / NO_FIRST / NO_LAST / MULTIPLE_LAST / HOLE`；offset 越界 `OFFSET_OVERFLOW`；嵌套 Fragment Header `NESTED_FRAGHDR`。不造字节、不截短、不挑第一份凑成功。
- **RFC 6946 atomic**：每个 `offset=0,M=0` 片段用带序号的独立 unit key，既不能填同 id 的普通组，也不会被那组的拒绝状态污染；两个同 id atomic 各自作为完整数据报送出。
- **预算**：`max_groups / max_fragments_per_group / max_total_fragment_bytes` 在分配任何重组缓冲**之前**核对，越界只产生 `LIMIT_*` 拒绝，绝不返回半成品；负数限额抛 `ValueError`。
- **输出**：在首片深拷贝上移除 Fragment Header，修正前一层 `nh` 与 `plen`，重新解析得到干净分组；上层 UDP/TCP 原字节逐位保留（测试用 sha256 核对）。输入 Packet 及其缓存不被修改。
- **报告卫生**：拒绝项只含分组身份、字节区间（offset/length 整数）和原因，不含任何应用正文。
